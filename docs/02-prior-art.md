## Closest work

### SpriteX32 (viknesh100, Hugging Face, Oct 2026): the direct functional competitor
From its model card (opened via raw README, 2026-11-04): "a small text-to-image model that generates 32×32 pixel-art sprites from English prompts"; a conditional U-Net with residual blocks and self-attention at the lowest resolution, **11.4M parameters**, flow matching, **50 Euler steps** by default, classifier-free guidance 3.0. The text encoder is frozen `openai/clip-vit-base-patch32` (pooled embedding). Trained 15,000 steps, batch 128, on one Colab GPU, on `tkarr/sprite_caption_dataset` (12,830 pairs). Its stated limitations: "colors and broad object types work much better than detailed or compositional prompts"; "only qualitative" evaluation, no FID. Weights licence: "other".
- **We checked its data:** sample rows of `tkarr/sprite_caption_dataset` are **Pokémon sprites captioned with Pokédex entries**, and the dataset card declares no licence. We do not use it.
- *Positioning:* SpriteX32 is what a GPU-sized tiny T2I model looks like. SpriteSheet aims for similar functionality under far harsher constraints (a spreadsheet, a single pass, ~1000× smaller text side), with licensed data, exact verification and quantitative evaluation. Head-to-head = C4 in doc 06.


### Freak in the Sheets (TreeHacks 2026)
- `clang --target=google-sheets main.c`: "a compiler that can run any piece of software inside a spreadsheet". The team built a custom ISA, a "2D memory architecture" (`row[col]` addresses), a two-pass assembler, and a from-scratch LLVM backend ("80% of the work").
- **Runs in the sheet:** a bytecode interpreter written in formulas, with code and data in the same memory. It steps the VM with Sheets **iterative calculation**, plus "an unpatched backend validation exploit in Google Sheets" so programs run "indefinitely without any user input".
- **Runs outside:** the clang/LLVM fork (`KevinL10/llvm-project-treehacks`, branch `fits`), a Bun/JS assembler, a Lua VM and preview tooling. The repo says it holds "about 10% of the work".
- ISA (`DOCS.txt`): `lte add mul sub set load store jmp0 jmp halt`.
- Perf trick: updates slow down as cells grow, so they **pack 16,666 32-bit ints into one cell** (15 bits per Unicode glyph, 3 glyphs per int, 50,000 glyphs per cell). That is why it looks like CJK text.
- **Not stated:** instructions per second, program sizes, how correctness was tested. No licence file. Devpost awards: "Most Technically Complex" and the Human Capital Fellowship Prize.
- *Takeaways for us:* (1) their lesson that cell count dominates performance applies to us too, so benchmark it; (2) we differ: they emulate a CPU, while we lower a neural network's dataflow graph straight into the sheet's own dataflow graph, which is non-iterative and recomputes on edit.

### Spreadsheets Are All You Need: GPT-2 Small in Excel (Ishan Anand)
- The forward pass of GPT-2 Small (124M) "entirely in Excel using standard spreadsheet functions", with no VBA. Release v0.7.0 `.xlsb` = **1,340,222,411 bytes** (~1.34 GB); the weights CSV zip = 596,953,205 bytes.
- v0.6.x needs Excel 365. v0.7.0 removed named functions / `LAMBDA` / `FILTER` so it runs in Excel 2021, accepting "slightly more complex formulas".
- Named functions (repo `NamedFunctions.md`): `softmax = LAMBDA(range, EXP(range-MAX(range))/SUM(EXP(range-MAX(range))))`, `layer_norm`, `gelu` (tanh approximation), and a BPE tokenizer spread across tabs (`Prompt_to_Tokens`, `vocab_bpe`, `id_to_tokens`).
- The Decoder reports: context limited to ~10 tokens without restructuring the weights; "roughly one token per minute"; recent Excel on Windows; macOS may freeze.
- **The author started in Google Sheets and moved to Excel because the model did not fit** (HN thread + The Decoder).
- Not stated: any check of outputs against a reference implementation. No licence.
- *Takeaways:* max-subtracted softmax (we do the same); their portability lesson (drop `LAMBDA`) matches our D-05; we differ by being **text→image, in Google Sheets, generated by a compiler, with exact parity gates**.

### Other spreadsheet compute
- **Doom.xlsx (2018):** a 3D raycasting engine in Excel formulas. Conditional formatting maps numbers → colours and number formatting hides the digits; VBA only for input. (Game Developer)
- **s0lly Raytracer-In-Excel (2019):** a formula ray tracer, ~1 frame / 2 s on an old PC; macros only for input/camera. (80.lv)
- **Excel LAMBDA is Turing-complete** (Microsoft Research blog, Jan 2021).
- MNIST/CNN classifiers in Excel exist (seen in HN comments and GitHub titles only; *not opened*). Every one found is a **classifier or tutorial, not a generator**.

### "AI image generation in Sheets" today
Every result found calls a remote API (SheetMagic `=AIIMAGE()`, DALL·E add-ons, Apps Script). Sheets' `IMAGE()` only shows a picture from a URL. Sheets pixel-art tutorials colour numbers with conditional formatting, after an LLM generates the grid *outside* the sheet. **No learned model running inside a sheet was found.** Searches for diffusion/GAN in Excel or Sheets found nothing.

### Nouns generative models (all outside spreadsheets)
- `jainr3/sd-nouns-model-lora`: an SD 2.1 LoRA trained on `jiovine/pixel-art-nouns-2k` (CreativeML OpenRAIL-M).
- `mistapproach/nouns-d-fusion`: SD 1.4 textual inversion on the first 300 Nouns at 256×256.
- Miguel Piedrafita, "Nouns text-to-image dataset" (Sep 2022): 50k random Nouns with auto-generated attribute captions, for fine-tuning SD. *Our caption approach (trait names → text) is the same idea; cite it.*
- *Comparison angle:* these use billion-parameter diffusion models on GPUs at 256–512 px. We use a model several orders of magnitude smaller, at native 32×32 with an exact palette, inside a spreadsheet. **Do not claim quality parity**; claim a different point in the design space, and if time allows, show pixel-exactness against the compositor, which SD-based models are not built to provide.

## Novelty claim (use this wording)
> "To our knowledge, the first text-to-image neural network compiled to native Google Sheets formulas, with no Apps Script and no external API."

Hedge: "no prior work found". Hobby projects (deepexcel.net, ExcelCNN) were not fully checked. **Do not claim** pixel rendering via conditional formatting as new (Doom.xlsx did it). The contribution is the compiler, the parity methodology, and fitting a generative model within Sheets' limits.

## Google Sheets limits (official docs)
- **Cells: up to 20 million cells or 100 MB per spreadsheet** (Drive help 37603). *Not* 10M as often quoted. No column limit is stated there.
- Characters per cell: the only official statement is that Excel conversion drops cells over 50,000 characters. Max formula length is not documented officially; "50k" is from third-party pages.
- Functions available: `LAMBDA LET MAP REDUCE SCAN MAKEARRAY BYROW BYCOL MMULT SEQUENCE TANH EXP HSTACK VSTACK WRAPROWS TOCOL XLOOKUP CHOOSECOLS UNICODE SPLIT` (function list, help 25273).
- Named functions: names up to 255 chars; recursion allowed but can hit "Calculation limit was reached while trying to compute this formula"; ranges inside are stored absolute.
- Calculation: Automatic/Manual mode exists (Manual for editors only). Iterative calc via `maxIterations` / `convergenceThreshold` (API `IterativeCalculationSettings`). Volatile recalculation interval: `ON_CHANGE`/`MINUTE`/`HOUR`.
- **Sheets API:** 300 read and 300 write requests/min per project, **60/min per user per project**; a batch counts as 1 request; no hard size limit but **~2 MB payload recommended**; 180 s processing per request; 429 when over quota. Plan uploads as ≤2 MB batches, ≤1/s.
- Conditional formatting: no rule-count limit stated; rules evaluate in order and the first match wins; custom formulas can only reference the same sheet unless you use `INDIRECT`. **Measure** with ~16+ rules over 32×32.
- Apps Script is irrelevant to us (not used), but for reference: custom functions get 30 s, scripts 6 min.
