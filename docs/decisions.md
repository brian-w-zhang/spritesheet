# Decisions log

Append-only. Format: `D-NN · date · decision · why · alternatives rejected`. Agents add entries when they change anything in `docs/04-architecture.md`.

- **D-01 · 2026-11-03 · Project = SpriteSheet, Advanced Technology, MP2.** A text-to-pixel-art model that runs as native Google Sheets formulas, compiled by our compiler Pixcell. *Why:* a hard medium constraint, exact pass/fail verification, a strong visual, and it fits a one-night build. *Rejected:* see the brainstorm in Brian's chat; the goose game stays as the MP3 candidate.
- **D-02 · 2026-11-03 · Dataset = Nouns trait art (CC0).** It comes with an exact compositor, so ground truth exists for *any* prompt.
- **D-03 · 2026-11-03 · Structured latent (slot prior + seeded sampler + conv decoder)** rather than an end-to-end regressor. *Why:* it allows exact two-level evaluation and avoids blur on under-specified prompts. It also mirrors the prior/decoder split of DALL·E 2. *Rejected:* end-to-end text→pixels with a noise vector (blurry, hard to evaluate); autoregressive pixels (1024 sequential steps); diffusion as MVP (too slow to build overnight; kept as a stretch).
- **D-04 · 2026-11-03 · The spec is numpy float64**, not PyTorch. All three engines (numpy, local spreadsheet engine, Google Sheets) are compared against it.
- **D-05 · 2026-11-03 · Portable formula subset for the core math**; Sheets-only functions are allowed only for tokenizer clean-up and rendering, each with its own real-Sheets check.
- **D-06 · 2026-11-03 · Exact integer PRNG (MINSTD LCG)** for sampling, because every intermediate stays below 2^53 and is therefore exact in every engine.
- **D-07 · 2026-11-03 · No AI attribution trailers in commits** (Brian's global rule overrides the course's `Assisted-by:` suggestion; AI use is disclosed in `AI-USE.md`). Brian may revisit this.
- **D-08 · 2026-11-03 · Verification stack = HyperFormula (primary, `smartRounding:false`, `useArrayArithmetic:true`) + LibreOffice headless with forced recalc and the stale-value check (secondary) + real Google Sheets (A4).** The tokenizer is also kept portable (SUBSTITUTE/MID/REPT/TRIM split, no SPLIT/REGEX), which narrows D-05: Sheets-only functions appear only in the render layer. Measured basis: `docs/05`.
- **D-09 · 2026-11-03 · Weights rounded to 15 significant digits before computing the reference**, because openpyxl's `%.16g` changes 43% of float64 values. `docs/05`.
- **D-10 · 2026-11-04 · Dataset pivot: Nouns → licensed emoji + pixel-art sources** (Noto, Twemoji, Fluent ×4 styles, OpenMoji, CLDR keywords, PixelGPT 20K, optional game-icons/Tabler/GameTileNet). *Why:* Brian wants "make anything", not NFT characters; 7 drawings per emoji concept teach concepts rather than one picture; variations keep exact targets for evaluation. *Rejected:* real-photo sets (blobs at sheet-sized capacity; taste-based eval), Kaggle pixel-art (16×16 JPEG, unclear provenance), tkarr/SpriteX32 data (Pokémon, unlicensed), bghira/PixilArt (murky provenance). - **D-13 · 2026-11-04 · Resolution plan: v32 first; v48 and v64 later as separate models and spreadsheets.** Native pixel art is integer-scaled or padded (never fractional); emoji/SVG are rendered natively at each N.
- **D-14 · 2026-11-04 · Course-guide files, raw data and models are not in the public repo** (guide §15 asks to not upload course material without permission; dataset licences). Teammate WatIAM IDs are not published.
- **D-15 · 2026-11-04 · One main all-sources model with a fixed sampling mixture + style ids; ablations (data scaling 5k/10k/18k PixelGPT, emoji-only) are short uncompiled runs.** *Why:* only one model needs the expensive compile + parity work; the data-scaling curve decides whether buying PixelGPT 216k is worth it. Canvas 32×32, with PixelGPT padded 1:1.
- **D-16 · 2026-11-04 · Build layout: per-tier dirs `data/build/tier{T}/`, one shared palette.** The palette (K = 32) is fitted once by k-means in CIELAB over a fixed sample (600 usable emoji concepts × all styles + 4,000 PixelGPT train sprites, 100k pixels from each family, seed 0) and reused by every tier, so a tier-0 model and a tier-1 model share class ids. Root `data/build/{palette,styles,concepts}.json` stay valid for code that reads them; `concepts.json` at the root is the full tier-1 list. *Rejected:* one palette per tier (class ids would change between tiers).
- **D-17 · 2026-11-04 · Colour snapping = nearest colour in CIELAB (CIE76); recolour variations snap within a hue window.** Base images snap to the nearest palette colour in Lab. A colour variation ("blue apple") hue-remaps only saturated palette classes (HSV s ≥ 0.25, v ≥ 0.2; greys and outlines are kept) and snaps each to the nearest Lab colour among palette colours within ±30° of the target hue (achromatic targets: low-saturation colours), implemented as a [K+1] lookup table per colour. A base is colourable if ≥ 15% of its foreground is saturated. Named backgrounds use the same candidate rule with distinct classes per name. *Why:* plain Lab-nearest sent "blue" to purple and "pink" to grey with this palette. *Rejected:* RGB nearest (worse on dark colours).
- **D-18 · 2026-11-04 · Concept filter and tiers.** Concept id = codepoints without fe0f. Excluded: Fluent/CLDR/OpenMoji groups Flags, Component and OpenMoji extras; regional indicators and tag sequences; skin tones; keycaps; ZWJ sequences in People & Body or containing person codepoints; single codepoints < U+2000 (©, ®, digits). Fluent people use their `Default` skin-tone folder. Result: 1,409 usable concepts (1,380 with all 6 emoji styles). Tier 0 = 60 concepts from each of Food & Drink, Animals & Nature, Travel & Places, Objects, Activities (single-codepoint first, most styles, then sha1 order); tier 1 = all 1,409 (≥ 2 styles) + PixelGPT 18k train / 1k val / 1k test. Symbols (many are coloured squares with glyphs) stay in tier 1. No quality_score filter on PixelGPT yet.
- **D-19 · 2026-11-04 · Held-out splits.** (concept, colour) and (concept, transform) pairs with sha1(cid|kind|value) % 10 == 0 are never sampled in training (every concept keeps ≥ 1 training colour and transform). One held-out keyword per concept where possible: a single-word keyword used by no other concept, not a generator word, not a PixelGPT caption word, not the plural of any name; 554 of 1,409 concepts have one (119 of 300 in tier 0). Held-out templates: 5 phrasings never used in training. Held-out drawings (a style of a concept) are not implemented yet.
- **D-20 · 2026-11-04 · Caption generator rules.** Captions are ≤ 12 words (tokenizer L), resampled otherwise, so no attribute word is ever truncated. Size variants are small/tiny only (the canonical render is already the largest); position (3×3 grid of the 16-px small block) and count ("two"/"a pair of", side by side) imply small; count only for names of ≤ 2 words (plurals). Keyword nouns in training captions are limited to keywords shared by ≤ 2 concepts, so "a food" never appears. PixelGPT captions are verbatim (lowercased), with an optional "pixel art" prefix and, on 30% of samples, a mirror/upside-down/background suffix; no size/position/count/colour on PixelGPT. Default mix: tier 1 45% emoji+variations / 30% PixelGPT / 25% emoji plain; tier 0 60/0/40. Built `bases_*.npz` are gitignored because they contain PixelGPT images.
- **D-30 · 2026-11-04 · Tokenizer split = "first token + remainder" per word, not the fixed-width `MID(…,(i-1)·100+1,100)` split.** `word_i = TRIM(MID(SUBSTITUTE(MID(rest_i,1,100)," ",REPT(" ",100)),1,100))`, `rest_{i+1} = TRIM(SUBSTITUTE(rest_i,word_i,"",1))`. *Why:* the classic split only works while the string is shorter than the field width; once the first words add up to ≥ 100 characters, later words fall out of their chunk (HyperFormula: twelve 10-letter words returned "" for word 11). The old Python twin also truncated to 99 chars, which no formula did. Now tokens longer than 100 chars are cut into 100-char pieces, the same in the formulas and in `tokenizer.py`. Intermediate strings stay ≤ ~10k chars (under the Sheets 50k cell limit). *Rejected:* `REPT(" ",LEN(clean))` (strings grow quadratically and can exceed the cell limit), `FIND` (not in the subset).
- **D-31 · 2026-11-04 · The style uniform uses two MINSTD steps** (`s1 = 48271·s0 mod M`, `u = 48271·s1 mod M / M`). *Why:* after one step u ≈ 2.2e-5·s0, so every seed below ~1000 (including the default seed 1) gave u < 0.023 and almost always style 1. After two steps, seeds 1–11 spread across [0, 1). Changed in `reference.lcg_uniform` (so `evaluate.py` follows), the `Latent` tab (B7 = s1) and docs/08.
- **D-32 · 2026-11-04 · Punctuation for the `clean` SUBSTITUTE chain lives in TEXT cells (`Tokens!H1:H32`), not in string literals.** *Why:* HyperFormula parses `\` as an escape inside string literals (`"\"` is a parse error, and that `#ERROR` propagated to every cell). Cell references are portable and also shorter.
- **D-33 · 2026-11-04 · Pixcell layout conventions.** Weight tabs store W transposed plus a bias column, so every unit is `SUMPRODUCT(x_row, W_row)+b`. V is stored transposed (`VT`). Conv activations are H×(W·C) interleaved inside a zero border, so each conv cell is a single SUMPRODUCT over a 3×(3·Cin) window and the matching kernel block, plus a per-channel FiLM shift row. Text is carried as a `Text` marker type: RAW for Sheets, a shared string in xlsx, a leading apostrophe in HyperFormula (otherwise "1", "true" or "1/2" become numbers, booleans or dates). Tab names cannot be read as cell refs (`Up_1`, `Conv_1`, `W_c1`, not `Up1`/`DEC1`). A lint (`pixcell/lint.py`) enforces the function subset, `MATCH(…,0)`, and SPARKLINE only in the display block. Full layout: docs/04 "Workbook layout".
- **D-34 · 2026-11-04 · LibreOffice oracle = one base xlsx, then per prompt a copy with the Prompt sheet XML patched (B2 inline string, B3 number) and 999 planted in every formula cell; all copies are converted in one soffice call.** *Why:* writing a 400k-cell xlsx per prompt is slow; patching one small XML part is not. The stale check is proven to bite (`test_libreoffice_stale_check_bites`: with RecalcMode = never, planted 999s survive and are counted).
- **D-35 · 2026-11-04 · Sheets push writes explicit per-cell formulas (values:batchUpdate, ≤ 1.8 MB per request, RAW for text, USER_ENTERED for numbers and formulas), not repeatCell/copyPaste.** *Why:* measured on the shared sheet, the full v32 shape (405k cells, 10.7 MB) uploads in 88 s with 15 requests, so templated fills aren't worth their complexity yet. The push replaces every tab (temporary tab → delete old → add new → delete temporary). Prompt→pixels latency: 6–14 s until the inputs show in the recalculated sheet, 11–18 s until Pixels is confirmed stable (half channels: 4–8 s / 8–11 s). Display: 12 px square cells achieved, SPARKLINE cells read back without errors (R3).
- **D-36 · 2026-11-04 · `tokenizer.index_vocab` lower-cases keys (first occurrence wins)** to mirror `MATCH(…,0)`, which is case-insensitive in every engine. It only matters if a vocabulary entry contains capitals.
- **D-21 · 2026-11-04 · v32 model budget from the R1 spike:** real Sheets recalculated a 127k-formula random-weight model in 6–14 s (first consistent read), and the pixels matched the reference. Conv cost is concentrated at 32×32, so capacity goes to the low-res layers: C0=128 (4×4), C1=64 (8×8), C2=48 (16×16), C3=32 (32×32), d=64. Target: ≤~30 s per prompt in Sheets.
- **D-40 · 2026-11-04 · v2 (masked discrete diffusion) compiles to per-step tab sets over one shared set of weight tabs.** Each denoising step gets its own `S{t}_*` tabs (Emb … Logits, Conf, Canvas); every step's formulas reference the same `W_*` tabs, and the FiLM shifts (`cond·F_i + f_i`) are computed once, because they do not depend on the step. Step 1's embedding is the constant MASK row. The same front emitter as v1 (`emit.emit_front`) builds the tokenizer, encoder and Latent tabs, so A1 and the v1 parity work carry over unchanged. Layout: docs/04 "v2 workbook layout". *Rejected:* a single denoiser tab set with iterative or circular recalculation (it is not portable, and Sheets' iterative calculation is not deterministic enough to gate).
- **D-41 · 2026-11-04 · Softmax confidence = `1/SUMPRODUCT(EXP(l − max))` in one cell per pixel, not 33 explicit EXP cells.** SUMPRODUCT forces array evaluation of `EXP(range − scalar)` in HyperFormula, LibreOffice and Sheets (a bare `SUM(EXP(range))` gives #VALUE in LibreOffice), which saves 33,792 cells per step. Argmax stays `MATCH(max, l, 0)−1` (first max, like numpy). The commit rule is `>=` against tau inlined as a Python `repr` literal (exact round trip). Every v2 gate reports, per step, the smallest |conf − tau| over still-masked pixels and the smallest top-1/top-2 logit margin, so that a near-tie (< 1e-9) cannot flip a commit silently.
- **D-42 · 2026-11-04 · The display / filmstrip colouring comes from one render spec (`emit.render_spec`), used by both the Sheets formatter and the xlsx writer.** It gives one conditional-format rule per class (0 = `#d8d4dd`, 1..K = palette, v2 adds MASK = K+1 = `#b9b4c2`), digits hidden with `;;;`, and square 12 px cells (xlsx: column width 12/7 = 1.71 units, row height 9 pt). The v2 filmstrip (one thumbnail per step, two per row below the display) uses the same 12 px grid, so every cell stays square without needing a second grid size. Random-weight v2 fixtures scale W_out (×3 or ×12 for the small A2 models, ×25 for the full-size spike) so that pixels commit at intermediate steps and every branch of the commit formula is exercised.
- **D-43 · 2026-11-04 · `LN` is allowed only in v2 `S{t}_Score` tabs, and only when cfg `temp` > 0 (seeded Gumbel-max sampling, `mdm.seeded_uniform`).** Each score cell is `l + temp·(−LN(−LN(u)))`, where u = `(MOD(48271·MOD(s1 + 104729·idx, M), M) + 0.5)/M` is computed inline from `Latent!B7` (exact integers below 2^53). chosen = `MATCH(MAX(score), score, 0)−1`, and conf = `EXP(INDEX(l,1,chosen+1) − max)·(1/sumexp)`. Measured LN parity on 400 hash uniforms: HyperFormula max rel 2.2e-16, LibreOffice 4.3e-15 (its 15-digit cached-value readback); the integer hash is exact. For temp > 0 the per-step margin reported is the score's top-1/top-2 margin. The lint enforces the tab restriction. At temp = 0 (the default) nothing changes, and no LN is emitted.
- **D-44 · 2026-11-04 · v2b global map compiles to one `GMap` tab (8×8·C3, `SUMPRODUCT(cond, W_g row) + bg`), computed once per prompt; every step's A3 cell is `MAX(0, conv + FiLM3) + GMap!…`** (it is added after the ReLU, as in `mdm.ref_denoise`). `W_g` stores Wgᵀ plus a bias column, with row j = (y·8 + x)·C3 + c. It is emitted only when the weights contain `Wg`, so v2a workbooks are unchanged.

- **D-51 · 2026-11-04 · v3 = 24×24, PixelGPT 216K only, learned variants instead of styles.** Brian bought the 216K pack (D-50 shows longer/wider training was the main lever; the remaining flaw is *mode averaging*: a one-shot net trained with per-pixel cross-entropy on many different "frogs" draws their per-pixel average).
  - *Data:* the 216K train split only (195,154 sprites), at its native 24×24 (no padding); emoji sources dropped, so there is one drawing style. Global palette refit to 48 colours (k-means in CIELAB; mean ΔE76 7.55 vs 8.86 at 32). Word table: the v1 words plus the 4,000 most frequent new caption words (V = 16,119; 97.4% of training-caption tokens covered). Augmentation: recolour + colour word (p 0.25), named background (p 0.08), leading article (p 0.5). Size and position words dropped (24×24 sprites fill the canvas).
  - *Anti-averaging:* the style slot becomes S unnamed **variants** learned by multiple choice learning (winner-takes-all): each sprite updates only the variant that already draws it best, with ε random assignments (1 → 0.05) so no variant starves. Assignments are cached per sprite and re-searched for 15% of each batch (amortised search). The variant head learns p(variant | prompt) from the winners; in the sheet the seed samples it exactly like v1's style, so the Pixcell formulas are unchanged. Variant models hide the style row.
  - *From the Five-Dollar Model paper (Merino et al. 2023):* multiplicative N(1, 0.15) noise on word vectors; optional larger kernels (`k1..k3`). Each conv cell is still one SUMPRODUCT, so a larger kernel adds capacity per formula, not formulas. Op parity at 24×24 with 5×5 kernels and 16 variants: `tests/test_pixcell_v3.py` → `parity_ops_v3.json`.
  - *Ops:* one GPU, so runs are sequential (`scripts/run_v3_queue.sh`). Two parallel runs exhausted unified memory and stalled; those runs are archived as `artifacts/runs/*_aborted_*`.
- **D-52 · 2026-11-04 · v3-P ("PatchGPT"): a fixed patch dictionary + a causal transformer prior over patch tokens, compiled as one causal formula grid.** *Why:* every one-shot or conv-decoder v3 averaged (D-51, v3_vq6: blur inside each code cell; sampled code grids mix sprites). Guidance on a stronger prior was the first real lever (r5: novel R@5 0.45). Moving all generation into a prior over *hard* patches makes blur impossible by construction.
  - *Dictionary:* K = 1024 hard 3×3 patches, fit by weighted k-modes on augmented training patches (`spritesheet/patches.py`; validation reconstruction fg accuracy 0.799). A sprite is 64 tokens, and decoding is `INDEX(W_D, code+1, offset)`.
  - *Prior:* the prompt's 12 word vectors (linear projection + position) are the first rows; image row L+t embeds code t. Pre-RMSNorm blocks (gains folded into the next weights at export), H-head causal attention whose weights are `EXP(q·k·scale)·keymask` with no max-subtraction (each weight is one cell), and a ReLU MLP. Final RMSNorm, then logits over K.
  - *Sampling:* `score = logit·(1/tau) + (−LN(−LN(u)))` with v2's exact integer hash uniforms (D-43; idx = t·K + k + 1), and `code_t = MATCH(MAX(score_row), score_row, 0) − 1`. Optional classifier-free guidance uses a second, smaller unconditional chain (`U*` tabs): `l = (1+g)·l_c − g·l_u`.
  - *One grid:* row n reads only rows ≤ n, and image row L+t reads Codes[t]. So the sheet's dependency graph runs all 64 sampling steps with no per-step tab copies; the formula count equals one teacher-forced pass.
  - *Spec and checks:* `reference_p.py` (row-by-row float64) is the spec. The torch twin agrees on codes (`tests/test_patchgpt.py`). Op parity on a random small model: HyperFormula max rel 4.8e-14, LibreOffice 4.2e-14, codes and pixels exact, with and without guidance (`tests/test_pixcell_p.py` → `parity_ops_v3p.json`).
  - *Lint:* `SQRT` is allowed in v3-P workbooks (RMSNorm), and `LN` only on the `Score` tab.
  - *Size:* dm 128, 4 layers, MLP 256 = 431,836 formulas (+144k with a dm-64 two-layer guidance chain). That is above D-47's ~250k comfortable upload size, so it uses the inert upload (D-48). The final width is set by measured Sheets latency.
- **D-53 · 2026-11-04 · v3-PG: grouped decoding, 8 rounds of 8 patches, because the 64-step causal grid is too slow in Sheets.**
  - *Measured* (D-52 model, random weights, 431,836 formulas, in the real v3 sheet): pixels equal to the reference for 2 prompts, but a prompt change took 128 s (inputs visible) / 148 s (stable) through the API. In the browser the sprite visibly filled in patch by patch for more than 2.5 min. Activating the whole `Score` tab at once made the spreadsheet return 404/503 for >15 min (row-by-row activation works).
  - *Reading:* Sheets' cost follows the sequential dependency depth (64 steps × layers), not total arithmetic: v1-XL does ~58M multiply-adds in ~3–4 s, and v3-P ~50M.
  - *Design:* prompt rows, then per group g a *query* row per patch (input `qpos[p]`, gives patch p's logits) and a *context* row per patch (input `E[code_p] + cpos[p]`; none for the last group). Still causal in row order, plus one rule: query rows are never keys for other rows (keymask constant 0, so no formula). Group g therefore sees the prompt and groups < g only (`test_grouped_only_sees_earlier_groups`), and the dependency depth is 8 rounds. The order is a fixed random permutation (`order_seed`), so groups are spread over the canvas.
  - *Spec and checks:* spec `reference_p.forward_g`, emitter `emit_p.compile_pg`, trace `trace_pg`; codes from the twin match the spec; op parity in both engines with and without guidance (`parity_ops_v3p.json`). Guidance uses an unconditional GroupGPT with no prompt rows and the same order.
  - *Size:* dm 96, 3 layers, MLP 192, 446,452 formulas. Latency test in progress.
- **D-54 · 2026-11-04 · v3-PG quality levers: sequence-level distillation, guidance distillation, cosine round sizes.**
  - *Why:* the grouped model trained on real data mixes "versions" of the object, because the patches picked in parallel within a round disagree. At 30k steps, novel R@5 is 0.25 against 0.38 for the causal model; colours per sprite are 3.94 against 3.50 for real sprites (r8, `colour_stats_r10.json`). Sampling tricks on the causal teacher only trade flat for noisy (r9/r10), so the gain must come from the prior.
  - *Distillation:* the grouped student trains on 75% causal-teacher samples and 25% real data (`gen_teacher_codes.py`, `--kd`). A teacher sample is one coherent drawing per (prompt, noise), which a parallel decoder can match.
  - *Guidance distillation:* the teacher's samples can be drawn with classifier-free guidance (causal unconditional prior `v3p_u`) and foreground min-p truncation (`patchgpt.pick`). The student then learns the guided distribution, so the sheet needs no second chain and stays at ~250k formulas.
  - *Cosine round sizes:* optional `sizes` in the config (`"cosine"` = [1, 4, 6, 8, 9, 12, 12, 12] for 64 patches in 8 rounds, as in MaskGIT). The first decisions are made almost one at a time, and the parallel picks come later, when the drawing is mostly fixed. The depth is still 8 rounds; context rows drop from 56 to 52. Spec, emitter and trace all follow `group_layout`, so the sheet path is unchanged: twin-vs-spec and HyperFormula/LibreOffice op parity pass with cosine sizes (`tests/test_patchgpt.py`, `tests/test_pixcell_p.py`).
  - *Teachers are never deployed*, so they can be any size (`v3p_b`: dm192 L6).
